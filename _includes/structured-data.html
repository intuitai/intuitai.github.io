Each area of the domain gets its own graph, because describing a book on a page about LLM routing (or the organization's software on a page of Python exercises) is noise that search engines discount: / the organization, its open-source projects, and both books /ep/* Everyday Programming, plus a breadcrumb back to the landing page /ep/exercis* the exercise set as a LearningResource /eai/* Everyday AI, plus a breadcrumb back to the landing page The organization node carries a stable @id so that the nodes referring to it within a page all mean the same entity. Be careful how much is expected of that: consumers resolve @id WITHIN a document, not across documents, so the two bare {"@id": ".../#book"} members the landing page lists are inert as a crawler signal -- a node object with no @type and no properties is simply dropped. They are kept as a cheap, valid statement of what belongs to the site, not because they carry the book's details over from the book's own pages. Anything a page actually needs asserted, it asserts itself.
